# FITTRACK — Architecture & Implementation Plan

## 1. Constraints and decisions

| Topic | Decision | Reason |
|---|---|---|
| Budget | 0 € (free Apple ID, public GitHub repo) | User decision |
| Build verification | GitHub Actions macOS runners (real Xcode, real simulators) | Development container is Linux; no local Xcode |
| Xcode project | Generated by XcodeGen from `project.yml`, generated `.xcodeproj` committed by CI | Deterministic target membership, no hand-edited `pbxproj` |
| Minimum OS | iOS 18.0 / watchOS 11.0 | SwiftData, Charts, Observation, VisionKit scanner; runs on iPhone 15 (iOS 26) and Watch Series 11 (watchOS 26) |
| Language | Swift 5 language mode, async/await, `@MainActor` view models | Modern concurrency without Swift 6 strict-mode churn on Apple delegate APIs |
| UI | SwiftUI only, French strings, `fr_FR` formatters | Requirement |
| Third-party dependencies | None | Requirement |

## 2. Architecture

MVVM + services, with a shared source folder compiled into both app targets.

```
Shared/            compiled into iOS and watchOS targets
  Models/          SwiftData @Model types (CloudKit-compatible)
  Domain/          Pure logic: nutrition targets, 1RM, progression, program generator
  Catalog/         Exercise library + default 5-day program
  Sync/            Codable DTOs exchanged over WatchConnectivity
  Persistence/     ModelContainer factory (local or CloudKit)
  Formatting/      French formatters
iOS/
  App/             @main, root tab view, dependency container
  Features/        Dashboard, Workout, Nutrition, Progress, Profile, Onboarding
  Services/        HealthKit, Open Food Facts, barcode scanner, photo recognition, phone connectivity
  DesignSystem/    Colors, cards, rings, buttons
Watch/
  App/             @main
  Features/        Workout list, active workout, rest timer, summary
  Services/        HKWorkoutSession manager, watch connectivity, offline outbox
Tests/             Unit tests (iOS + watchOS), UI tests (iOS)
```

### Persistence & sync

* **SwiftData** is the source of truth on each device.
* All models are **CloudKit-compatible** (every attribute has a default, all relationships optional, no unique constraints). Each record carries a stable `uuid` used for de-duplication.
* **iCloud (CloudKit private database)** requires a paid Apple Developer Program membership. The code path exists (`ModelContainerFactory` with `cloudKitDatabase: .private(...)`) and is switched on by the `FITTRACK_ICLOUD` compilation flag plus the iCloud entitlement. With a free account it stays off and the app is fully local. Exact enabling steps are in the README.
* Conflict policy: CloudKit/SwiftData last-writer-wins per record; workout sessions are immutable once finished, and duplicates (same `uuid`) are merged by a de-duplication pass at launch.

### iPhone ↔ Watch

* **WatchConnectivity**:
  * iPhone → Watch: `updateApplicationContext` with the training program and the latest weights (latest state wins, delivered when the watch wakes).
  * Watch → iPhone: `transferUserInfo` with each finished workout (queued by the system, delivered when the phone becomes reachable — offline-safe).
  * The Watch also keeps its own SwiftData store, so it works fully without the phone.
* The iPhone imports received workouts idempotently by `uuid`.

### HealthKit

* Read: body mass, active energy, heart rate, steps, workouts. Write: strength workouts (`traditionalStrengthTraining`), body mass, dietary energy/protein/carbs/fat.
* Watch uses `HKWorkoutSession` + `HKLiveWorkoutBuilder` for live heart rate and active energy.
* Authorization state is displayed honestly; denied/unavailable states are handled.

### Nutrition

* Built-in generic food database (common raw foods, per 100 g), searchable offline.
* **Open Food Facts** search + barcode lookup (no key).
* **Barcode**: VisionKit `DataScannerViewController` (real camera).
* **Photo**: Apple Vision `VNClassifyImageRequest` on-device classification → food labels mapped to French search terms → user confirms the food and the quantity. No portion estimation is claimed.
* **Halal**: three-level status — declared halal by Open Food Facts label (not certified), unknown, or potentially non-halal ingredient detected (pork, alcohol, gelatin, etc.). Nothing is labelled halal without a source.

### Workout reliability

* Each validated set is persisted immediately (`modelContext.save()`), so an unexpected termination keeps the in-progress session; on next launch the app offers to resume it.
* Timers are wall-clock based (start date + accumulated pause), not tick counters, so they survive backgrounding.

## 3. Verification pipeline (CI)

1. `xcodegen generate`
2. Build iOS app (includes embedded watch app) for the iOS Simulator
3. Build watch app for the watchOS Simulator
4. Unit tests on iPhone 15 simulator
5. Unit tests on Apple Watch simulator
6. UI tests (launch, navigation, core workflows) on iPhone 15 simulator, with screenshots
7. Commit regenerated `.xcodeproj`, publish ZIP artifact

## 4. What cannot be verified in CI

Camera (barcode/photo) on real hardware, real HealthKit data, real iPhone↔Watch pairing, CloudKit. These are listed as "to test on device" in the delivery report.
